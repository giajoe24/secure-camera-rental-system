# 想定問答集(中間報告・指導員・顧客)

答え方は 3 段:**ひとことで → しくみ(どこで・どう) → なぜ**。
「しくみ」はファイル名と関数名が言えれば十分。細かいことは「プログラム解説.md の ○ 章」を見せる。

---

## まず覚える 5 つの考え方

ほとんどの質問は、この 5 つのどれかで答えられる。

| | 考え方 | ひとことで |
|---|---|---|
| ① | **記録は追加するだけ** | 「解錠」→「完了」か「取り消し」の行を足していく。書き換えない・消さない |
| ② | **施錠を確かめてから完了** | 棚が開いて、また閉まったのをスイッチで見てから「完了」 |
| ③ | **安全側に倒す** | 記録できなければ開けない。開けられなければ記録を取り消す。停電中は閉まったまま |
| ④ | **待つ処理で画面を止めない** | 社員証の読み取りは別スレッド、それ以外の「○秒後」は after() |
| ⑤ | **追加機能は 1 機能 1 ファイル** | config.py で ON / OFF。MUST_ONLY = True で MUST だけの動き |

答えに詰まったら:「そこは ○○.py の △△ でやっています。細かいところは確認して後でお答えします」。

## A. 全体

**A1. これは何をするシステム?**
- ひとことで:社員証をかざすと、セキュアカメラの棚の鍵が開いて、誰がいつ借りて返したかが自動で記録されるシステム。
- しくみ:タッチ画面で操作 → RC-S380 で社員証を読む → 電磁ロック LE-53 を外す → 棚が閉まったら記録。
- なぜ:今まで誰が持っているか分からなくなる、記録が手書きで残らない、を解決するため。

**A2. どんな部品でできている?**
- ラズパイ 4(本体)、7 インチのタッチモニター、RC-S380(カードリーダー)、LE-53(電磁ロック、スイッチ付き)、MOSFET(ロックを動かすスイッチ)。
- プログラムは Python。画面は customtkinter、記録は SQLite。

**A3. 貸出の流れを説明して。**
- ホーム →「カメラを借りる」→ 社員証 → 貸出時間を選ぶ → 確認画面で「借りる」→ ロックが開く → 棚を開けて取り出して閉める → 完了 → ホーム。
- しくみ:screens.py の画面が順番に切り替わる(HomeScreen → ScanScreen → TimeScreen → ConfirmScreen → UnlockScreen → DoneScreen)。
- 返却も同じで、時間の代わりに返却の確認画面(ReturnConfirmScreen)が入る。

**A4. MUST と WANT はどう分けた?**
- MUST は 11/18 の顧客 MTG で確定した 23 項目。docs/MUST一覧.txt に、できた・実機で確認した、の印つきでまとめてある。
- WANT は追加機能。1 機能 1 ファイルにして、config.py で ON / OFF できる(⑤)。`MUST_ONLY = True` にすれば MUST だけの動きになる。

**A5. なぜラズパイと Python?**
- ラズパイ:GPIO(ロックとスイッチ)、USB(カードリーダー)、画面を 1 台でまとめて扱えて、安い。
- Python:nfcpy(RC-S380)と gpiozero(GPIO)のライブラリがそろっていて、PC でも同じプログラムを動かせる。

## B. 記録(一番聞かれる)

**B1. 貸出はどう記録している?**
- ひとことで:棚が閉まって施錠を確かめてから「完了」として記録する(②)。
- しくみ:「借りる」で db.py の `start()` が「解錠」の行を書いてからロックを外す。UnlockScreen の `watch_lock()` が 0.2 秒ごとにスイッチを見て、閉まったら `finish()` が「完了」の行を足す。
- なぜ:開けただけで記録が成立すると、本当に借りたか分からない記録ができてしまう。MTG でそう指摘されて、この形にした。

**B2. どこに記録している?**
- `data/camera_rental.sqlite3`(SQLite)。テーブルは users(利用者)と logs(操作の記録)。
- Excel(`exports/rental_log.xlsx`)は貸出・返却が終わるたびに DB から作り直すコピー。
- なぜ SQLite:サーバーが要らない 1 ファイルの DB で、途中で失敗したら取り消す(rollback)仕組みがあるから。

**B3. 今貸出中かどうかは、どうやって分かる?**
- db.py の `current_rental()`:「完了」の行のうち一番新しいものが「貸出」なら貸出中、「返却」なら返却済み。
- 「解錠」や「取り消し」の行は見ないので、棚を開けただけでは状態が変わらない。

**B4. 借りた人と返した人を分けて記録できている?**
- できている。1 回の操作ごとに行を足していて、行ごとに「操作した人」(user_id)が入る。
- 貸出の「完了」の行 → 借りた人、返却の「完了」の行 → 返した人。
- `list_rentals()` が 2 つを組にして、Excel の「貸出一覧」(借りた人・返した人が並ぶ)を作る。

**B5. 記録を書き換えたり消したりできない?**
- logs には追加しかしない(①)。延長も書き換えではなく「延長」の行を足す。
- 利用者を消しても、記録がある人は行を残してカードだけ使えなくする。だから過去の記録の名前は消えない。

**B6. 記録は誰が見られる?**
- 管理者だけ。管理画面(管理者の社員証で入る)と、ラズパイの中の Excel。
- 履歴は名前・期間で検索でき、「ファイルに保存」で Excel と CSV にできる。

## C. ロックと機器

**C1. ロックはどうやって開けている?**
- ひとことで:GPIO18 から 5ms だけ電気を出して、MOSFET 経由で LE-53 に電流を流す。
- しくみ:lock.py の `open()` が `on()` → 5ms 待つ → `off()`。
- なぜパルス:LE-53 は一度外れれば、棚を閉めると勝手にまたロックされる(スナッチロック)。流しっぱなしにしなくていいので、熱も電力も少ない。実機で 2ms あれば外れたので、余裕を見て 5ms。

**C2. なぜ MOSFET が要る?**
- GPIO は 3.3V で小さい電流しか出せないので、ロックを直接動かせない。MOSFET を電子のスイッチにして、5V の電源からロックに電流を流す。
- ダイオードは、ロックのコイルを切ったときに出る逆向きの電圧を逃がして、MOSFET を守るため。

**C3. 棚が閉まったことはどう分かる?**
- LE-53 についているマイクロスイッチ(NO)を GPIO23 で読んでいる。施錠中だけ GND とつながって Low になる。
- lock.py の `is_locked()` が True / False を返す。外付け 10kΩ でプルアップしている。
- 線が切れたら High のまま =「開いている」になるので、不正な開放の警告が出て、故障に気づける。

**C4. 社員証はどう読んでいる?**
- card_reader.py の `read_card()`。nfcpy で RC-S380 を開き、かざされたカードの ID(16 進の文字)を返す。
- 最大 30 秒待ち、「戻る」が押されたらすぐやめる(`should_stop()`)。

**C5. 停電したらどうなる?**
- 棚は閉まったまま(LE-53 は電気を流したときだけ外れる)(③)。
- 解錠の途中で止まった場合は、次に起動したとき `close_unfinished()` が「取り消し」を書くので、記録がおかしくならない。

**C6. カードをコピーされたら?**
- 正直に:今はカードの ID だけで判定しているので、ID をまねできれば通ってしまう可能性はある。
- 社内の棚で、記録が全部残ること・不正な開放は検知されることで抑止している。強くするならカードの暗号化された領域を使う、が次の手。

## D. 画面

**D1. 社員証を待っている間、画面が固まらないのはなぜ?**
- 読み取りを別スレッドでやっている(④)。
- gui.py の `ThreadPoolExecutor(max_workers=1)`(concurrent.futures)に読み取りを頼み、ScanScreen が 0.1 秒ごとに「終わった?」(`future.done()`)を見に行く。
- 作業員を 1 人にしているのは、カードリーダーの取り合いを防ぐため。

**D2. 7 インチで見やすくした工夫は?**
- 800×480 に合わせて作り直した。ボタンは高さ 56px 以上(指で押しやすい約 10mm)、文字は 16px 以上。
- 状態は色だけでなく必ず文字でも出す(「貸出可能」「警告」など)。点滅は使わない。
- 押すボタンは青。赤はエラー、黄は注意、緑は完了だけ(安全色の意味とそろえた)。

**D3. ちらつきはどう直した?**
- 原因は 3 つ:ホームを 30 秒ごとに作り直していた、画面の切り替えで一瞬空白が見えた、タッチ後にボタンの色が残った。
- ホームは作り直さない、次の画面を作り終えてから前の画面を消す(gui.py の `show()`)、ボタンの hover を切った。

**D4. ロックが急に開いてびっくりしない?**
- 確認画面に黄色の枠で「押すと棚のロックが開きます」と先に出している(`show_unlock_notice()`)。
- 開いたあとは大きく「棚のロックが開きました」と、次にすることを出す。

**D5. 放っておいたら?**
- 操作がないまま 30 秒たつとホームに戻る(gui.py の `every_second()`)。
- 棚が開いている間だけは戻さない(開いたまま画面が消えると困るので)。

## E. 異常のとき

**E1. 棚を開けなかったら?**
- 30 秒(`UNLOCK_WAIT_SECONDS`)開かれなければ「取り消し」を記録して、状態は変えない(UnlockScreen の `give_up()`)。

**E2. 棚を閉め忘れたら?**
- 60 秒(`UNLOCKED_WARN_SECONDS`)たつと黄色の枠で「棚が閉まっていません」と出して、「閉め忘れ」として記録する。閉めたら完了になる。

**E3. こじ開けられたら?**
- 1 秒ごとに、プログラムが解錠していないのにスイッチが「開いた」になっていないかを見ている(forced_open.py の `check()`)。
- そうなったら赤い警告の画面を出して「不正な開放」を記録する。部品の追加なしで、今のスイッチだけでできる。

**E4. SD カードがいっぱいになったら?**
- いっぱいになる前に:空きが 500MB を切ったら記録して、ホームに警告を出す。古いファイルは自動で消す(storage_check.py)。
- 本当にいっぱいになったら:「解錠」の行が書けないので `start()` がエラーになり、ロックは開かない(③)。テストでわざと DB をいっぱいにして確かめている。

**E5. Excel が作れなかったら?**
- 貸出・返却は止めない。正式な記録は DB にあって、Excel は DB からいつでも作り直せるから(③)。

**E6. エラーが起きたらどうなる?**
- gui.py の `show_error()` が、エラーの種類ごとに利用者向けの文に直してエラー画面を出す。プログラムは落ちず、ホームに戻れる。
- 解錠の失敗などは「できごと」に記録して、管理者が後で見られる。

## F. 開発・テスト・これから

**F1. どうやってテストした?**
- 自動テスト 44 件(`python -m unittest`):記録の順番、取り消し、容量不足で開かないこと、延長、検索など。
- PC で試すモード(`USE_HARDWARE = False`):社員証と棚をテスト用ウィンドウのボタンで代わりにして、全画面を通した。
- 実機:カードリーダー、解錠パルス、スイッチ、7 インチの全画面、貸出 → 別の人の返却まで確認済み。

**F2. 一番苦労したところは?**
- LE-53 が外れなかったこと。テスターで電圧を測って、線やブレッドボードでの電圧降下が原因だと分かった。パルスの長さも試して 2ms で外れると確かめた。
- 顧客 MTG で「本当に返したか分からない記録ができる」と指摘されて、記録の作りを「施錠を確かめてから完了」に作り直したこと。

**F3. 追加機能は何がある?**
- 利用者向け:期限切れの表示、延長(誰でも)、日をまたぐ貸出(最長 31 日)、ロックが開く予告。
- 管理者向け:管理画面(登録・一覧・停止・部署・履歴の検索・ファイル保存)、できごとの記録、不正な開放の検知、バックアップ、容量の見張り。
- 一覧は docs/WANT一覧.txt。

**F4. まだできていないことは?**
- 実機で確かめる:30 秒の取り消し、60 秒の警告、こじ開けの警告、待ち時間の決定。
- WANT:期限切れの音(スピーカー待ち)、Teams 通知と別の端末から見る(社内ネットワークの許可が要る)。
- 回路:はんだ付けと、太く短い配線。
- 複数物品はやらない(DB・画面・ロックとスイッチが物品の数だけ要り、見合わない)。

**F5. もう 1 台作るときは?**
- `.py` をコピーして `pip install -r requirements-pi.txt`、スタートアップを設定するだけ。DB の足りない列は起動時に自動で足す。
- 設定は config.py にまとまっている(GPIO の番号、待ち時間など)。

**F6. カメラが本当に中にあるかは分かる?**
- 分からない。分かるのは棚の開け閉めだけ。
- 確実にするなら、重さのセンサーなどでカメラがあるかを見る必要がある(今回は見送り)。
